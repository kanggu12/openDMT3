# Test cases

One table per area. **Checked by** points at what checks the case, as `` `file#text` ``: the text is a test's name or
a line the check prints, and `tests/test_docs.py` fails when either is gone. **Stage** says where it runs
([testing.md](testing.md)):

- `unit`: `./dmt3 test` (`python -m tests.parallel`; one process: `python -m unittest discover -s tests -t .`) (`unit*`:
  only with `OPENDMT3_GAME_DIR` set to the client data's folder; `unit (root)`: only when the tests run as root, on
  Linux)
- `ui`: the launcher's screens, `tests/e2e/ui/run.sh`
- `web`: the site's screens, `tests/e2e/web/run.sh`
- `wine`: the real client and the built installer under Wine, `tests/e2e/windows/`
- `gpu`: the same on the PC's own graphics card, on WSL 2 only (`OPENDMT3_WINE_GPU=1`, `tests/e2e/windows/gpu/`)
- `load`: a server process on a made-up history of 300,000 plays with 64 stand-in cabinets (one of them bad), 20
  visitors on the site and a greedy program, `python tests/e2e/load/cabinets.py` (30 minutes)
- `native`: the in-game layer's own tests, `native/cardreader/test.sh` (MinGW, then Wine, in containers)
- `ci`: only in [CI](testing.md#ci)'s jobs, the server's image and the launcher built on Windows
- `hand`: by a person, on a Windows PC
